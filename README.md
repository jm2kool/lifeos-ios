# Matinee

An independent film diary for iPhone, inspired by Letterboxd. It's built for iOS 26: Liquid Glass controls, a pure-black OLED theme, and sign-in with Apple, Google, email, GitHub, Discord, X, Facebook, Microsoft or Spotify — or no account at all.

Matinee is not affiliated with Letterboxd.

## Install

Every push to `main` builds an unsigned `.ipa` on GitHub's Macs and attaches it to the **latest** release. Install it with [Sideloadly](https://sideloadly.io) using your Apple ID, the same way you install LifeOS. The **preview** release has simulator screenshots and a short screen recording.

## Film data

Films, posters, cast and recommendations come from [TMDB](https://www.themoviedb.org), the same database Letterboxd uses. You need a free **API Read Access Token**: sign up, then go to Settings → API.

- **In the app:** paste the token into the card on the Films tab, or under Settings → Film data.
- **Built in:** add it as a repository secret named `TMDB_TOKEN`. CI writes it into `Config/Info.plist` at build time, so it never sits in the source code.

## Sign-in setup (Google, Apple and the rest)

Sign-in goes through a free [Supabase](https://supabase.com) project. Supabase handles every provider in one place, so no client secrets are stored in the app.

1. Create a project at supabase.com. Copy the **Project URL** and the **anon / publishable key** from *Project Settings → API*.
2. Go to *Authentication → URL Configuration* and add the redirect URL `matinee://auth-callback`.
3. Go to *Authentication → Sign In / Providers* and turn on the ones you want:
   - **Email**: on by default. It works with no extra setup.
   - **Google**: in Google Cloud Console, create an OAuth client of type *Web application*. Set its authorised redirect URI to `https://<your-project>.supabase.co/auth/v1/callback`, then paste the client ID and secret into Supabase.
   - **GitHub, Discord, X, Facebook, Microsoft (Azure), Spotify**: same pattern. Make an OAuth app on that site with the Supabase callback URL above, then paste its ID and secret into Supabase.
   - **Apple**: needs a paid Apple Developer account, for a Services ID and key.
4. In the app, go to **Settings → Account server** (also on the sign-in screen) and paste the URL and key. To have them built in instead, fill `MatineeSupabaseURL` and `MatineeSupabaseAnonKey` in `Config/Info.plist`, or add the `SUPABASE_URL` and `SUPABASE_ANON_KEY` repository secrets.

The sign-in screen asks the server which providers are switched on and only offers those: Apple and Google get their own buttons, email opens a form (sign in, create an account, reset a password), and the rest sit under **More**.

### Optional: sync your library to your account

Run this in Supabase's SQL editor. Once it's in place, your diary, ratings and lists follow your account to any phone.

```sql
create table if not exists public.libraries (
  user_id uuid primary key references auth.users on delete cascade,
  doc jsonb not null,
  updated_at timestamptz not null default now()
);
alter table public.libraries enable row level security;
create policy "own library" on public.libraries
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

### Optional: public profiles

Your name, photo, favourite films and shows, and Currently watching go into a `profiles` table that anyone can read, so people can find you in Search (type `@username`) or open a `matinee://u/username` link. Your diary, watchlist and ratings stay in the private `libraries` row.

```sql
create table if not exists public.profiles (
  user_id uuid primary key references auth.users on delete cascade,
  handle text check (handle is null or handle ~ '^[a-z0-9_.-]{1,30}$'),
  name text not null default '',
  bio text not null default '',
  avatar_url text,
  avatar_data text,
  favorites jsonb not null default '[]'::jsonb,
  favorite_shows jsonb not null default '[]'::jsonb,
  currently_watching jsonb not null default '[]'::jsonb,
  updated_at timestamptz not null default now()
);
create unique index if not exists profiles_handle_key on public.profiles (handle);
alter table public.profiles enable row level security;
create policy "profiles are public" on public.profiles for select to anon, authenticated using (true);
create policy "insert own profile" on public.profiles for insert to authenticated with check ((select auth.uid()) = user_id);
create policy "update own profile" on public.profiles for update to authenticated
  using ((select auth.uid()) = user_id) with check ((select auth.uid()) = user_id);
create policy "delete own profile" on public.profiles for delete to authenticated using ((select auth.uid()) = user_id);
```

### Optional: friends, the feed, Blend and watch parties

Following, the friends feed, a shared watchlist for Blend and watch parties need a few more tables. Copy the SQL from **Settings → Friends → Copy setup SQL** and run it in Supabase's SQL editor (it's safe to run again). It adds:

- `follows`: who follows whom (public, and you can only change your own follows)
- `activity`: diary entries you choose to share (off until you switch on **Share my diary with followers**)
- `parties`: watch-party timers, found by their six-character code
- `watchlist` and `persona` columns on `profiles`: your watchlist is published only if you switch on **Show my watchlist for Blend**
- `delete_my_account()`: lets **Settings → Delete my account** remove the sign-in itself. Every table above (and `libraries`, `profiles`) is tied to the account and goes with it. Without the function, the app deletes your rows and signs you out, and the sign-in has to be removed in the Supabase dashboard.

Older servers without these columns keep working: the app falls back to publishing the profile without them.

### Optional: the watchlist widget on sideloaded builds

Sideloadly with a free Apple ID drops the permission that lets the app and its widget share files, so the widget sends your watchlist through your Supabase project instead. In the app, open **Settings → Widget → Copy setup SQL**, paste it into Supabase's SQL editor and run it once. Each phone reads only its own row, identified by a private device ID.
